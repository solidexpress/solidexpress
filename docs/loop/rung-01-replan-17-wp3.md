## Why (verified on `main` 1a1cc6a)

- **Dead first clicks.** In sx-037 one retry was needed on: rail **Sketch**, **Jaw** click 1, **Circle** centre, Smart Dim, Select on a thin line. #202 fixed chip / HUD clicks reaching the canvas; #206 fixed the thin-line pick radius (screen-pixel tolerance). The headless suites push a *teleported* click (motion + press + release in one frame, `_x11_click_screen`) and are green, so the remaining drops are not the stale-hover case alone. A canvas press is dropped silently in three places before it reaches `sketch_mode.click`: `_input` (~5073) sketch branch `if _over_chrome(mouse_pos) or not _viewport_owns_pointer(mouse_pos): return`; the `_finish_click_shield` STOP overlay (`_arm_finish_click_shield` ~5990, released by `_release_finish_click_shield_on_motion`); and `sketch_mode.click()` (~4520) returning early when a **dimension label** under the point opens the editor (`dimension_hit` -> `_emit_dimension_edit`) instead of placing the point. Nothing records which one fired, so the walker cannot tell. Candidate causes to test: (C1) hovered control is a large STOP container whose rect contains the canvas point (`_pointer_hits_control(h, pos)` true) after a rail press; (C2) first press after a LineEdit had focus (`_release_numeric_if_press_elsewhere`); (C3) a label text rect at the click point (Circle centre at the origin after the jaw labels exist); (C4) the press and release arrive in the same frame (xdotool `click`) and the release path treats a first click as a drag end; (C5) window-focus click (not product).
- **Marquee.** The sketch Select tool has no box select. `_sketch_input` press branch (~3158): Select + nothing under the pointer calls `sketch_mode.click(p2)` -> `_select_at` (~2306), which clears the selection. Part mode has a Ctrl+drag `BOX_SELECT` (`_on_release` ~3944, `document_view.select_in_rect`), bodies only. `command_registry.gd` advertises window/crossing but nothing implements it for sketch entities.
- **Face vs body.** `document_view.gd` `select_ray` (~1094) is two-stage by design: a click on an **unselected** body selects the body; a click on the **already selected** body refines to an edge (within tolerance) or the hit face. After Extrude, Fillet apply and sketch exit the body is the current selection, so the next click gives a face (N17, chunk 1); after `Esc` / New nothing is selected, so the first click gives the body (A7). The status prints only `Selected <8 chars of an id>`, so the level is invisible.

## Decisions (final)

1. **Click ledger.** `ViewportInteraction` gets `var last_click_disposition := ""` and `signal click_disposition(text: String)`. Every **left press** that reaches `_input` while a sketch is active, or reaches `_handle_model_pointer`, sets it to exactly one of: `sketch-click:<TOOL>` (`<TOOL>` = `SketchMode.Tool.keys()[tool]`, e.g. `sketch-click:CIRCLE`), `sketch-drag:<TOOL>`, `sketch-box:SELECT`, `drop:over-chrome:<control name or "rect">`, `drop:not-owner:<hovered control name>`, `drop:shield`, `drop:dim-label:<index>` (the press opened a dimension editor instead of placing geometry), `model-click`. When the environment variable `SX_INPUT_TRACE` is `1`, also `print("[input-trace] press (%d,%d) %s" % [x, y, text])`. No status text, no UI.
2. **Real-window probe, not a CI suite.** `tools/gui_click_probe.sh` (bash + `xdotool`, `DISPLAY=:1`) launches `tools/godot/godot --path game` with `SX_INPUT_TRACE=1`, waits for the window, and for each of four sequences runs 20 trials (File -> New between trials is not needed; Esc to reset): (1) rail **Sketch** then Escape; (2) rail **Jaw** then canvas click; (3) rail **Circle** then canvas click; (4) rail **Select** then click a line. Coordinates come from `xdotool getwindowgeometry` and the 1280x800 layout in `docs/loop/rung-01-replan-17-checklist.md` chunk 1; if a coordinate misses, print it and stop. It prints `trial n: <disposition>` per trial and a tally `<sequence> <dead>/<20>`. It uses `xdotool mousemove X Y click 1` (no sleep) for one pass and `mousemove`, 80 ms sleep, `click 1` for a second pass.
3. **Fix what the ledger shows, nothing else.** (a) `drop:over-chrome` on a canvas point: the named rect belongs to a stale or oversized control; exclude it in `_over_chrome` / `_tree_blocks_pointer` (never widen the canvas by ignoring real chrome) and add that control to the test. (b) `drop:not-owner`: fix `_viewport_owns_pointer` for that control class. (c) `drop:shield`: release the shield on the first motion or after 250 ms, whichever is first. (d) `drop:dim-label` for a **draw tool** click that is not inside the label's own text rect: use the text rect only (the 22 px / 6 mm halo stays for Select). (e) `sketch-click` with no entity added: find the early `return` in `sketch_mode.click` and name it in the PR. (f) Not reproducible in 2 x 80 trials after fixing the above: the PR says so with the tally, leaves the ledger in place, and the item is closed as soft-GL / environment (a window-focus click). **Do not** add retries, timers or "double click" tricks.
4. **Sketch marquee.** Select tool, left press on **empty canvas** (no constraint glyph, no dimension label, `drag_hit(p2).is_empty()`, `_nearest_entity_at(p2) == ""`): a drag longer than `CLICK_SLOP` draws a rectangle (`_box_rect`, drawn by `_draw`) and on release selects entities. Left-to-right = **window** (every sample point of the entity inside the rectangle, rectangle fill blue `Color(0.35, 0.6, 0.95, 0.18)`); right-to-left = **crossing** (any sample point inside, or the polyline crosses the rectangle; fill green `Color(0.35, 0.85, 0.45, 0.18)`). Shift or Ctrl held on release adds to the current selection, otherwise it replaces it. A press that moves less than `CLICK_SLOP` is the old click (clears the selection). Dimension labels and constraint glyphs are **not** marquee targets; deleting entities already prunes their dimensions (`_prune_orphan_dimensions`). The 8-entity cap in `_select_at` does not apply to a marquee. A press that starts **on** an entity still starts the existing drag-move.
5. **Status wording.** Select statuses name the level: `Selected body <id8>`, `Selected face <id8>`, `Selected edge <id8>`, and for a box select `Selected body <id8>`; multi-select stays `<n> selected`. Sketch: `Selected 1 sketch entity` for one, `Selected <n> sketch entities` for more, `No sketch entities` for none (both the Ctrl+A site and the marquee). Every existing prefix test (`begins_with("Selected ")`) still holds.
6. **Face vs body is by design (documented, no behaviour change):** first click on an unselected body = body; click on the selected body = edge (within pick tolerance) or face; Esc clears. The hover hint text is unchanged.
