### Soft-GL protocol (sx-041 walker)

Rules 1–16 (replan 10), 17–22 (11), 23–30 (12), 31–36 (13), 37–40 (14), 41–44 (15), 45–51 (16, 17) stay as in [`rung-01-replan-17-checklist.md`](rung-01-replan-17-checklist.md); rules 52–60 (re-PLAN 18) stay as in [`rung-01-replan-18.md`](rung-01-replan-18.md); rules 61–71 (re-PLAN 19) stay as in [`rung-01-replan-19.md`](rung-01-replan-19.md) (61 no batching, ever; 62 lag waits; 64 pointer placement; 65 a fresh save is proven by the file; 66 face sketch with the rail hiding Sketch; 67 a dead click or key is evidence; 68 burst readback; 69 jaw geometry is measured; 70 popups: one click opens, one click chooses; 71 engine log noise is counted) **with these amendments**: rule 63 (timing rows) is replaced by rule 72; the app's hint trace kind is `kind=hint|restore`; rule 70's popups now include the finish-bar Op / End / Thin dropdowns (`FinishOp`, `FinishEnd`, `FinishThin`) and the HUD View ▼ (`HudView`), each of which prints `[popup-trace] show` on the opening click and `hide` after the choice; rule 71's noise now also counts `ERROR: Signal 'tree_exited' is already connected` (rule 77); rule 69's jaw points read `H`, `H + (20·s, 0)` and `H + (20·s, −10·s)` (A8) or `H + (20·s, −48.4·s)` (A8w, A8r).

New in this plan (sx-040 walkers lost 2.5–5.4 s per tool call, recorded rule-61 breaks without voiding them, tapped Shift instead of holding it, and could not see a label the product never drew):

72. **Judge timing from the trace, never from the walker's clock.** Every timing clause is judged only from timestamps the app prints (`t=` on `[status-trace]`, `[hover-trace]`, `[input-trace]`, `[popup-trace]`, `[key-trace]`), relative to the traced event that **started the clock** (usually the `kind=result` line), never relative to a walker-side `date +%s.%N` taken before a tool call (sx-040: N8b's Open click landed 5.4 s after T0; N16's pointer move took ~3.8 s). `date` is no longer required for N16 / N8b; an app-side Δ is computed from two trace lines.
73. **Place the pointer before the clock-starting event.** A clause that needs the pointer "somewhere within N s" is rewritten so the pointer is placed (and its pixel written, rule 64) in an earlier call; the second half is judged by **trace order** (for example "after the `[hover-trace] … target=none` line no `kind=hint|restore` line follows"), which holds at any tool latency.
74. **`headless-only` clauses are not walked.** A clause marked `headless-only` (sub-latency timing: the exact 2.5 s hold edge, a hint within 1.0 s of the hold end) is proved by a named headless suite and printed in A15. The walker records the row's walkable clauses only and writes `headless-only: see <suite>`; it never records PARTIAL for them.
75. **Voided rule-61 breaks are redone.** sx-040 recorded but did not void rule-61 breaks in N1a (two parallel wheel notches), N21b (clear and click sent in parallel), A11d (Ctrl+A sent before the click's screenshot returned; two pointer moves in parallel) and N14 (`2.5` and Enter in parallel). Those verdicts are **void**; sx-041 redoes them one action per call: N1a one wheel notch per call, N21b the clear click and the position click as separate calls, A11d Ctrl+A only after the click's screenshot is read, N14 `2.5` and Enter as separate calls. A row whose evidence includes a parallel pair is written `voided` and redone.
76. **Modifier keys are held, not tapped.** For Shift / Ctrl clauses (N24b): call 1 `xdotool keydown shift`; call 2 the drag (one drag, rule 61); call 3 `xdotool keyup shift`. Read the press line's `shift=` / `additive=` and the `[key-trace] … pressed=1` / `pressed=0` pair in `$OUT/input-trace.log`. A tap (`xdotool key Shift`) is never a held modifier; a held-Shift drag whose press line says `shift=0` is a walker failure (redo), not a product failure.
77. **Engine `tree_exited` noise.** `ERROR: Signal 'tree_exited' is already connected` (one per jaw label click in sx-040: A8w, A8) joins the rule-71 noise: count it per chunk, never judge by it.
78. **Draw, then read the labels (A8r).** After every `Jaw committed` read the **drawn** labels before any edit: crop the full-resolution screenshot around the jaw, list every dimension label by text and physical pixel box, and write the rail's right edge (≈ 129 physical px). A label list read from the status line, the Timeline or the inspector instead of the picture is PARTIAL; a `°` label that is missing, clipped or under the rail is FAIL (RC1), whatever the status says.
